OpenAI's Jalapeño Chip Beats Nvidia Blackwell on Inference Benchmarks

At Hot Chips, OpenAI shared the first measured results for Jalapeño, its custom inference ASIC co-developed with Broadcom. On SemiAnalysis's InferenceX benchmark it delivered 1.5–1.9x more AI work per watt and 1.7–3.6x lower end-to-end latency than comparison Nvidia GB200/GB300 systems across GPT-OSS 120B, DeepSeek R1 and Kimi K2.5 1T.

Jalapeño is rated at 700W but sustained at or below 550W in testing, versus the 1,200–1,400W packages it was compared against. OpenAI says the full-stack design — model, serving software, chip, memory and network built together — lets it minimise data movement and keep the KV cache local. SemiAnalysis notes the A0 stepping already beats Blackwell and even edges Vera Rubin's July MTP numbers on single-token-prediction throughput per megawatt, with a B0 stepping in the fab promising ~25% more perf-per-watt. OpenAI plans small-volume deployment by end of 2026, ramping in 2027, and will not replace its Nvidia partnership — Jalapeño is a first-party complement, not a substitute.

AgentFlow: A 7B Model Beats GPT-4o by Learning the Workflow

An ICLR 2026 oral paper (top 1.1% of submissions) from Stanford, Texas A&M, UC San Diego and Lambda shows that training an agent's workflow — not just the model — can beat far larger systems. With a 7B open model, AgentFlow surpasses GPT-4o across ten benchmarks spanning search, agentic reasoning, math and science.

The sharpest finding is the training method. Training the planner in-the-flow with a new Flow-GRPO method added 17.2% performance, while conventional offline supervised fine-tuning made things 19.0% worse — same model, opposite outcomes. Gains over GPT-4o ranged from 4.1% to 14.9% across benchmark groups. The work suggests that learning a better workflow can matter as much as scaling the model, a potentially cheap lever for capability gains.

Source: Lambda Labs / ICLR 2026, 25 August 2026

Japan Adopts AI Transparency Principles, Urges Training-Data Disclosure

Japan's government adopted guiding principles on intellectual-property protection for generative AI operators, calling on businesses to disclose an outline of the data and methods used to train their models. The Principles Code is not legally binding but is designed to boost transparency.

Operators that adopt the code will notify the government and publish on their websites the learning processes, types of training data and collection methods for their generative AI models. They will also disclose whether training data could lead to copyright infringement if requested by users and rights holders, subject to conditions. The code covers both domestic businesses and overseas operators providing AI in Japan, and arrives as the EU AI Act's transparency obligations took full effect on August 2.

NVIDIA Ships CUDA Python 1.0 With CUDA 13.3

NVIDIA released CUDA Python 1.0 alongside CUDA 13.3, providing official, NVIDIA-maintained libraries that give full access to the CUDA platform directly from Python. The release brings semantic-versioning commitments and stable APIs.

Key components include cuda.core (Pythonic runtime access), cuda.compute (CCCL parallel algorithms), cuda.bindings (1:1 C-API bindings), cuda-pathfinder and nvmath-python. The shared foundation lets kernels run against CuPy arrays or PyTorch tensors without copying data — PyTorch now depends on cuda.bindings in its CUDA wheels. The move makes Python a first-class, supported way to program NVIDIA GPUs, bridging low-level control and high-level convenience without manual binding maintenance.

Ultralytics 8.4.128 Tightens OpenVINO Batch Inference

Ultralytics released version 8.4.128, switching OpenVINO to synchronous batch inference to eliminate hangs in AsyncInferQueue, particularly for dynamic INT8 batches on CPU. The update also reduces RAM use during training and sharpens TensorRT INT8 export.

OpenVINO now submits each input batch as a single synchronous request using the LATENCY performance hint, avoiding the indefinite hangs that plagued async mode. TensorRT 7–10 keeps only detection-head Sigmoid layers in higher precision, reducing model size and improving inference speed while preserving confidence. Documentation now covers tracking modes across detection/segmentation/pose/OBB models, adds local Docker build instructions, and clarifies augmentation behaviour and Android ExecuTorch setup.

Why Production RAG Needs More Than Vector Search

A detailed analysis argues that a basic embed-and-retrieve prototype breaks down once corpora grow and queries become unpredictable, and that production RAG is fundamentally about reliable context, not the LLM. It breaks down hybrid search, graph retrieval, agents and evaluation as the missing layers.

The piece walks through an ingestion pipeline of parsing, chunking, metadata and careful vectorisation, then explains why a single vector query is insufficient — combining keyword and semantic search (hybrid), adding graph retrieval for multi-hop dependencies, and layering re-ranking and agentic retrieval. It stresses that without an evaluation harness measuring recall, precision and answer faithfulness, teams cannot tell whether retrieval is actually improving. The takeaway: treat RAG as a retrieval-engineering problem with the LLM as just one component.

Source: Towards AI, 25 August 2026
